# Second-pass verifier reports, 2026-10-08: PRs #150, #151, #152

Condensed from the verifier agents' final reports (the raw transcripts live only in the session's
scratch area). Each verifier was told to try to falsify, ran only on synthetic data under a
redirected profile, and did not edit or push. SHAs are the heads they tested.

## #151 `fix/dedup-bounded-wal` (tested `579bfbd`, base main `fceded4`): FAIL-WITH-CAVEAT, then fixed
- CONFIRMED: output identical to old code across 40 combinations (plain / ANALYZEd index x floor x
  window/chunk), including hardlink groups, unreadable first names, ino=0 buckets, a 900-member bucket.
  Max WAL on a 45,000-row synthetic index: old 20,628,872 B, new 984,712 B (no reader); both
  21,119,152 B with a foreign read transaction held for the whole pass (NOT bounded; the disk guard
  is the backstop, which aborted cleanly before the disk filled).
- DEFECT D1 (medium-high): the disk guard ran at the start of every `find_duplicate_clusters`, so
  with <2 GB free the candidates list and review page returned HTTP 500 even with a hot cache.
  Fixed in `ddcabc0` (guard only before a stage that has files to hash; typed 503
  `dedup_insufficient_disk` on the two read endpoints; test through the real API; mutation shown).
- D2 message rounding, D3 docstring: fixed. ADR-0040 addendum records the long-reader limit, the
  up-front size snapshot (stale view possible where the old code crashed with `database is locked`),
  the fail-open guard, and the log-level changes.

## #150 `fix/review-clusters-use-warm-cache` (tested `a61c651`): no blocking defect
- CONFIRMED: no deadlock or second dedup pass with concurrent selector/warm/review/explanation/
  summary calls (`find_duplicate_clusters` called once); typed 409 body identical on all routes;
  no stuck-409 (clusters None counts as cold in three places); mutation of service.py back to main
  fails 10 of 12 tests, and four single-line mutations each fail a named test.
- D1 (medium-low design regression): MCP `preview_apply`/`delete` read the same cache, so
  `selection_hash` stopped detecting on-disk changes (only the executor preflight remained: a
  modified duplicate was skipped as `size_or_mtime_changed_since_scan`, nothing lost). Fixed in
  `6cc90af` (`delete` re-stats selected files, refuses with `SelectionMismatchError`).
- D2 (cancel does not stop a selector already blocked on the lock; documented), D3 (Explain button
  showed a red 409; now waits, `a23eaff`), D4 (docstring).
- Found later by the integration verify, not the verifier: a test wrote `config.toml` into the cwd
  (fixed `b0f6bad`).
